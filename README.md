# My Bill Book backend

## Local setup

1. Install PostgreSQL and create a database named `my_bill_book`.
2. Copy `.env.example` to `.env` and set `DATABASE_URL` to your local PostgreSQL credentials. Replace `AUTH_SECRET` with a random secret at least 32 characters long. Set the demo user's name, email, and password in the `SEED_USER_*` values. Use a password with at least 12 characters.
   To enable automatic customer details from GSTIN, subscribe to the provider's plan on RapidAPI and set `RAPIDAPI_KEY` in this backend `.env` file. The key stays on the server and is never sent to the browser. Check the API's Pricing tab for its current free quota and billing terms.
3. From this folder, install packages and create the Prisma client and database tables:

   ```powershell
   npm install
   npx prisma generate
   npx prisma db push
   npx prisma db seed
   ```

4. Generate the Prisma client with `npm run db:generate`, then start the API with `npm run dev`. It listens on `http://localhost:3000`.
5. In `D:\billing\front`, copy `.env.example` to `.env`, run `npm install`, then `npm run dev`.

The seed command creates or updates the user specified by `SEED_USER_EMAIL`. It stores a bcrypt hash, never the plain password. The login page posts to `/api/auth/login`; successful sign-in returns an eight-hour signed token used for `/api/auth/me`.

## Product master API

All product routes require the bearer token returned by login. Product records belong to the signed-in user, and SKU values must be unique within that user's catalog.

- `GET /api/products?q=&stock=` lists products. `stock` accepts `in`, `low`, or `out`.
- `POST /api/products` creates a product.
- `PUT /api/products/:id` updates a product.
- `DELETE /api/products/:id` deletes a product.
- `GET /api/gst-rates` lists the signed-in user's GST rates.
- `POST /api/gst-rates` creates a custom GST rate.
- `PUT /api/gst-rates/:id` updates its name, percentage, description, or active state.
- `DELETE /api/gst-rates/:id` deletes a rate that is not assigned to products.

## Customer master API

All customer routes require the bearer token returned by login. Customer records belong to the signed-in user.

- `GET /api/customers?q=` lists customers and can search by name, phone, email, or GSTIN.
- `POST /api/customers` creates a customer.
- `PUT /api/customers/:id` updates a customer.
- `DELETE /api/customers/:id` deletes a customer.
- `GET /api/customers/gstin/:gstin` looks up registered business details for a valid GSTIN using RapidAPI. This requires `RAPIDAPI_KEY`.

The frontend Customer Master page uses these endpoints. Customer records are stored in PostgreSQL rather than browser storage. After changing `schema.prisma`, run `npm run db:push`, `npm run db:generate`, then restart the API.

## Sales invoice API

All invoice routes require the bearer token returned by login. Invoices belong to the signed-in user and store item, price, HSN, and GST snapshots.

- `GET /api/invoices` lists the latest 200 invoices.
- `GET /api/invoices/:id` returns an invoice with its customer and items.
- `POST /api/invoices` creates an invoice from a customer and product quantities. The server calculates GST from each product's assigned rate.

The Sales page creates and prints invoices. Invoice numbers are generated by the API.

- `GET /api/dashboard` returns sales totals, invoice status counts, a seven-month sales series, and recent invoices for the signed-in user.
